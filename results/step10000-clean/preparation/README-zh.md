## 新增及调整

1. `prepare_model.py`：复用已验证的 CPU 导出、严格部署加载工具，分阶段执行；不会启动训练。导出后校验完整分片 SHA256，记录训练来源。导出权重分片实测共 25,503,889,812 字节，约 25.50GB（23.75GiB），另有少量处理器配置。
2. `model_source.py`：固定来源为本项目 10000 步模型，校验训练配置文件哈希、训练器的规范 JSON 配置签名、导出清单、严格加载记录、分片尺寸与修改时间。完整哈希在准备阶段复核；每个客户端不重复扫描 25.5GB。
3. `prepare_inputs.py`：冻结 500 个计划槽位，与旧基线的实际种子和指令配对，并记录官方任务源码哈希。旧基线实际有效策略回合为 459，成功 43；另外 41 个槽位因专家异常没有执行策略，单独呈现，不把它们计作有效策略失败。
4. `common.py`：沿用逐回合 JSONL、每任务与整体汇总，增加模型来源启动校验。每回合立刻追加并 fsync；成功率分母使用实际有效策略回合。
5. `serve.py`：部署一份 10000 步模型，握手返回 checkpoint 步数和来源哈希；FP32、eager、关闭 compile。两个会话共享权重，推理串行，不自动合批。
6. `session_policy.py`：复用已验证的隔离实现。会话私有动作缓存、步数与 Python/NumPy/Torch CPU/CUDA 随机状态；FeatureTransform 在锁内切换并恢复。reset 不能重置另一会话。
7. `evaluate_task.py`：复用官方仿真任务、成功判据、动作和步数上限。检查实际指令与基线一致，逐次核对返回的 session ID、计数与随机种子。小测增加双会话 reset 屏障，保证两个会话都重置后再发首个动作请求。未新增换种子、失败重试、平滑或精度调整。
8. `driver.py`：启动模式必须明确指定 `--smoke-only` 或 `--full-suite`。小测不会自动转完整评测。一个推理服务、两个仿真进程；异常或结束只清理自己创建的进程组。小测每任务最多 30 分钟，异常停止且不自动重启。
9. `start_full.py`：用户手动启动的后台完整评测入口。先核对小测、配置、代码哈希和模型来源一致，再执行静态检查。完整评测支持单路入口。
10. `static_check.py`、`test_launch_gates.py`、`test_recovery.py`、`check_session_isolation.py`：覆盖任务数、路径、配置、来源、启动模式、指令漂移、重复计数、专家异常、断点续跑和会话状态隔离。11 项控制流程测试及独立会话隔离测试通过。另在本地增加配置签名回归测试，通过。

准备期间发现新增校验把“配置文件字节哈希”和“训练器计算的规范 JSON 签名”混淆，已修正并增加回归检查；保留原始错误日志及后续验证记录，没有重训或改权重。

## 正式评测配置

- 官方 50 个任务，每任务 10 个计划策略回合，合计 500；小测完成的两个有效回合计入这 500 个槽位，正式入口跳过已完成槽位。
- `task_config=demo_clean`，`instruction_type=seen`。
- 同一份 10000 步微调权重；不使用官方 RoboTwin 后训练权重。
- FP32、eager、compile 关闭，动作 chunk 返回，`use_length=50`。
- 不保存视频、逐帧图片或完整观测轨迹。终端日志每任务上限 2MiB、服务上限 16MiB；结构化结果不截断。正常完整结果与日志预计远低于 200MB，缓存可能另外增长，均放在本项目 `cache`。

## 逐回合保存和恢复

每任务保存 `tasks/<task>/episodes.jsonl`、`expert.jsonl`、`summary.json`；整体保存 `summary.json`、`comparison.json`。记录任务、setting、指令类型及实际指令、三个种子、成功/失败、步数、耗时、异常、会话 ID。专家调用与策略评测分别记账。

正常重新启动会跳过已完成的成功或失败回合，不覆盖失败。中断回合保留单独标记，默认不自动重跑；必须核对后显式传 `--retry-interrupted`，使用相同种子及指令续跑。策略异常、专家异常不会被算成成功，也不会以新种子替换。专家无异常但失败且元数据有效时，继续原种子的策略评测，与旧基线口径一致。

## 资源与限制

GB10 使用统一物理内存，不把“显存”和系统内存相加。启动前要求 GPU 没有其他计算进程且可用统一内存至少 85GiB；运行时每两秒检查一次，低于 16GiB 储备则停止本次自有进程。资源守卫不能替代避开并发重负载的安排。

完整评测预计约 6–8 小时，依据旧模型的整轮耗时估计；不同模型成功所需步数、任务异常与其他负载会影响实际耗时。两回合小测不能预测完整成功率或最长任务耗时。

官方原始 `robotwin.json` 的数据来源仍不据此自行宣布符合 clean-only。本轮沿用训练和原基线使用的、从允许的 V3 clean 数据计算的统计文件 `configs/normalization/robotwin_clean_v3.json`，SHA256 为 `0b5ed854065e9c64e1b8934c274c38d0efa062d743bfad071f1a089983125611`，保留原有来源证据。

专家预检查是否计入官方五次采集配额、官方“场景”的配额范围仍待确认；本轮保留官方检查、分别计数，不宣称全局配额已经由官方确认。两路并行属于工程调度方案，并非官方逐项认证。
