# 模型训练与仿真评测报告

团队：连仿真都做不到的话。整理日期：2026年10月24日。

本报告说明最终选用的20,000步模型、训练适配、仿真评测设置及实测结果。所有次数均以原始日志为依据，未将未执行或异常回合补写为有效结果。

## 1. 实验目标与模型来源

在单台 NVIDIA GB10服务器上，基于比赛指定的 `robbyant/lingbot-vla-v2-6b` 原始预训练模型，对 RoboTwin中 Aloha-AgileX 的50个任务进行 clean数据联合微调，并评估模型在 clean与 randomized场景中的任务完成表现。

本次材料选用累计20,000次优化器更新后的同一份完整 HF权重。未使用官方 RoboTwin后训练模型初始化，未按任务选择不同模型或 checkpoint。配置中的 `post_training=true`表示本地微调运行模式，不表示初始化来自官方后训练权重。

## 2. 数据与训练设置

训练使用50任务 clean V3数据，每任务50条演示，共2,500条、548,893帧。randomized数据仅用于评测，未参与训练。模型使用顶部、左右手腕三路图像，图像尺寸224，动作 chunk长度50。状态/动作字段映射及归一化参数见冻结配置。

|项目|实际设置|
|---|---|
|硬件|ARM64 Linux、NVIDIA GB10，约119.7GiB统一内存|
|模型规模|总参数约6.376B，可训练参数1,938,090,551|
|参数更新范围|冻结Qwen骨干；动作专家及相关对齐组件参与训练|
|视觉处理|视觉分支参与前向，冻结其参数不等于删除视觉模块|
|批量|micro batch=1，梯度累积8，有效 batch=8|
|优化器|AdamW|
|内存适配|梯度检查点；数据worker=0、pin_memory=false|
|精度与注意力|参数保留FP32，训练配置启用混合精度；eager attention，关闭compile|
|辅助学习|深度、未来深度和未来视频损失权重各0.004；教师资源与开关见冻结配置|

训练分为两阶段：第一阶段至10,000步，基础学习率2e-5；第二阶段恢复完整训练状态，基础学习率1e-5，按冻结的余弦调度继续10,000步，累计至20,000步。这里的“步”是优化器更新次数，不是动作 chunk数，也不是每个任务各自训练的次数。

逐参数更新范围、配置、数据选择与恢复证据分别位于 `training/step_10000`、`training/step_20000`。本报告不以推测替代这些记录。

## 3. 保存、导出与资源管理

正式训练每1,000步同步保存 DCP，两个阶段合计按最近两份的策略保留训练状态。训练期间不并发生成完整 HF导出，避免保存时额外构造一份全量权重带来的统一内存峰值。推理模型在训练结束后经 CPU单独导出，并进行严格加载核验。

20,000步 HF目录包含18个文件，约25.52GB，含六个 safetensors、模型索引、配置、tokenizer和 processor；不含优化器、数据加载器游标及 RNG恢复状态。完整 DCP与 HF推理目录用途不同，后者不提供完整续训恢复能力。

评测采用一份常驻模型和最多两个仿真 worker。服务按会话隔离 reset、动作缓存、计数、FeatureTransform和随机数状态，请求串行处理，无自动合批。保留单worker入口；两路调度是本项目的工程实现，不代表赛事方逐项认证。

GB10的系统与GPU使用统一内存池，统计时只计算一份。clean评测采样最低可用统一内存约61.69GiB；最终 randomized＋unseen重测约54.61GiB。结果保存关闭视频、逐帧图片和完整观测轨迹，主要输出为 JSON、JSONL及有上限的文本日志。

## 4. 评测协议与记录口径

最终模型覆盖官方50个任务，每任务每种场景计划10回合。clean使用 `demo_clean`＋`seen`，randomized使用 `demo_randomized`＋`unseen`。场景、动作含义、任务成功判据和官方步数上限保持原设置。

任务索引为t、回合索引为i时：环境seed为100000+i，策略seed为1000000+1000×t+i，指令seed为2000000+1000×t+i。计划与实际指令均保存，任务调度顺序不改变种子规则。策略失败不换seed重跑或覆盖。

unseen结果来自真实重测。配置约束、客户端传参与官方生成器选池一致；每个有效回合记录实际文本、候选数量及候选池SHA256。35项CPU回归检查通过，两个真实技术验证回合计入计划500回合。小测检查执行链路，不以任务是否成功作为技术通过条件。

`policy_completed`表示有效策略回合，成功和到达步数上限的正常失败均计入分母；专家阻塞、初始化异常、中断和未开始分别统计。每完成一回合，先追加并同步结果，再清理环境。断点恢复按任务与回合索引去重，保留历史尝试。

## 5. 实测结果

|模型与用途|场景|指令|计划回合|有效回合|成功|有效回合成功率|
|---|---|---|---:|---:|---:|---:|
|原始预训练对照|clean|seen|500|459|43|9.37%|
|10,000步对照|clean|seen|500|458|43|9.39%|
|20,000步选用模型|clean|seen|500|455|65|14.29%|
|20,000步选用模型|randomized|unseen|500|423|43|10.17%|

最终模型两场景合计处理1,000个计划槽位，形成878个有效策略回合、108次成功。121个专家阻塞槽位和1次初始化异常不计入有效策略回合。合计108/878约12.30%只用于描述这两组记录，不是官方场景加权排名分数。

唯一的初始化异常位于 randomized中的 `put_bottles_dustbin`、seed100000，发生在物体稳定性检查阶段，日志字段为 `policy_exception`。其余正常策略失败完整保留。没有未闭合策略尝试，评测服务和worker均已退出。

20,000步模型在本次有效回合集合中的 clean成功率高于两个对照，但各组有效回合覆盖不同，且每任务样本量较小。本实验未据此进行严格的因果推断、显著性判断或对更多训练步数效果的外推。

## 6. 来源文件与复现

最终合并结果为 `results/results.json`，来源为 `results/step20000-clean/results.json`和 `results/step20000-randomized-unseen/results.json`，校验值见 `results/aggregation-manifest.json`。逐任务CSV、原始策略/专家事件、冻结配置、指令与seed可相互核对。

普通Git仓库保存源码和小型记录，权重通过 Release分发。提交ZIP的03目录包含选用的20,000步完整HF模型。外部数据、教师资源、仿真资产和运行环境需另行按官方来源及许可部署。

原部署路径与校验指纹用于追溯既有实验。新机器应建立新运行目录，适配依赖和来源检查并重新完成小测；HF-only入口的独立部署尚未完成从零实测。具体目录映射及检查命令见 `docs/REPRODUCTION.md`。

## 7. 规则对应与待核实事项

依据2026年10月24日取得的[官方赛题与Q&A](https://tianchi.aliyun.com/competition/entrance/532514/information)：clean2clean使用seen，clean2random使用unseen；受时间或算力限制不足100次时按实测次数提交，最终以官方复测为准。

专家五次采集配额按发起次数计算、与seed无关，采集失败后仍应继续policy测试。本实现对专家场景元数据的依赖仍导致121个槽位阻塞，属于需要披露的流程差异，当前成功率不覆盖这些槽位。clean归一化统计来自允许数据并有技术证据，统计方法尚未得到赛事方单独确认。

官方字段模板附件需要登录下载，当前JSON仍为 `lingbot_quick_results_v1`，尚未完成官方字段映射。目录、权重与数据校验通过不替代这项格式核对。团队未提供05真机创新和06小红书活动材料，本包仅整理01—04。尚未向天池提交。
